# AX08

A general-purpose, 8-bit computer. Noteworthy features include:

- 8 general purpose register.
- 16 bit address space
- 27 different instructions, the documentation for which can be found [here](./AX08/instruction_set.md).
- Each instruction can be conditionally executed.
- 2 IO Ports.
- A clock speed of up to 20k instructions per second.


## Variants

### AX08

The complete implementation of the AX08 computer specification.

### AX08L

The AX08L also called AX08-lite is a simplified variant of the AX08 computer implementing only a subset of the AX08 operations. It was created during the development of the AX08 platform to test the core system.

The following operations are supported:
- All load operations: `LOAD`, `LOAD2`
- The logical operations `LOGIC.AND` and `LOGIC.XOR`
- The arithmetic operation `ARITHMETIC.ADD`
- The shift operations `SHIFT.SHIFT_LEFT` and `SHIFT.SHIFT_RIGHT`
- The negative decode operation `DECODE.NDECODE`
- All memory operations: `MEMORY.LOAD`, `MEMORY.STORE`
- All IO operations: `IOx.POLL`, `IOx.READ`, `IOx.WRITE`
- The break operation: `BREAK`

Not supported are:
- The logical operations `LOGIC.NAND`, `LOGIC.OR`, `LOGIC.NOR`, `LOGIC.`
- The arithmetic operations `ARITHMETIC.SUBTRACT`, `ARITHMETIC.ADD_WITH_CARRY`, `ARITHMETIC.SUBTRACT_WITH_CARRY`
- The positive decode operation `DECODE.DECODE`

Additionally there are a few cases of special behaviour in the AX08L variant:
- There is no carry flag.
- The break instruction causes a value to be written to the output register. This is fixed via a firmware patch in the sequencer_v1 firmware.
- The page register write address is incorrectly configured as `0b1011` instead of `0b1010`.
- The `DECODE.NDECODE` instruction always returns `0xFF` if bit 3 of `A` is not-zero.

The last quirk allows detecting the AX08L architecture at runtime:

```
# 0b1111_1110 - AX08
# 0b1111_1111 - AX08L
R1 = NDECODE 0b0000_1000
R1 += 1
if R1 == 0 {
    # Only executed on AX08L
}
```


## Defining undefined behaviour

None of the following facts should be taken for granted:

- The initial state of the carry flag on boot is undefined.

- Using any unused opcode results in garbage written to the instructions output register if its condition evaluates to `true`.

- Writing with `LOAD2` to an unused address is a nop.

- Reading an unused register address produces an undefined value.
